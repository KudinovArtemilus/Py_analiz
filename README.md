# Анализ .shp файлов пресса OP1: норма, аномалии, деградация

## Что внутри файла .shp (разобрано)
* Один файл = один цикл пресса, ~90 с, запись каждые **10 мс**.
* Заголовок: время старта (Windows FILETIME, UTC) + количество каналов.
* **256 дискретных** сигналов (клапаны Y, датчики S, режимы) + **307 аналоговых** float32
  (ползун, гидростанция, 12 насосов, 6 дренажей насосов MD1–MD6, сервоклапаны, CCyl/LCyl, MB, выталкиватели,
  номер заготовки/плавки, ходы штампа).
* Запись = 1264 байта: счётчик (4) + биты (32) + аналоги (307×4).

## Самый простой запуск (PyCharm)
Открыть `run.py`, при необходимости поправить настройки вверху (папка `D:\press`, OP1/OP2, QUICK) → правый клик → **Run 'run'**.
Сначала с `QUICK = True` (каждый 20-й файл, минуты), потом `QUICK = False` (всё). Результаты — в `D:\press_shp_analysis\results`.
`analyze.py` сам по себе без аргументов не запускается — ему нужен файл признаков от `extract_features.py`.

## Главное — «Диагноз по узлам»
В начале отчёта и в файле `diagnosis.txt` (печатается и в консоль) — вывод простым языком по каждому узлу:
светофор НОРМА / НАБЛЮДАТЬ / ПРОБЛЕМА, цифры, вероятная причина, что проверить на месте, прогноз.
Пороги (давление зажима, температура масла, давление) — в начале `diagnose.py`, словарь `LIMITS`: уточните по паспорту пресса.

## Как запустить (на компьютере, где лежат 190 ГБ)
Проще всего — `run_all.bat` (там уже `D:\press`, OP1 и OP2): для каждой операции отдельно — сначала быстрый пробный отчёт по каждому 20-му файлу (`report_quick_OP1`, `report_quick_OP2`), потом полный (`report_OP1`, `report_OP2`).

Вручную:
```
pip install -r requirements.txt
python extract_features.py D:\press --op OP1 -o features                 # всё
python extract_features.py D:\press --op OP1 --from 2026-09-01 --to 2026-09-30 -o sep   # только сентябрь
python analyze.py features.parquet --op OP1 -o report
```
* `--op` — если в D:\press лежат и OP1, и OP2: норма у разных операций разная, анализируйте раздельно.
* `--from/--to` — период; папки других дней даже не открываются.
* Если данные на обычном HDD (не SSD), ставьте `-j 2` или `-j 3`: больше потоков только мешают диску.
* Можно указать подпапку напрямую: `python extract_features.py D:\press\2026\09 ...`

Старый вариант запуска:
```
pip install -r requirements.txt
python extract_features.py D:\shp_data -o features -j 8     # ~0.1 с/файл на ядро; упрётся в скорость диска
python analyze.py features.parquet -o report
```
Или поправить путь в `run_all.bat` и запустить его.

Посмотреть любой цикл целиком (все сигналы + диаграмма дискретных) или сравнить несколько циклов наложением:
```
python plot_cycle.py D:\shp_data\OP1_20260928_000825.shp
python plot_cycle.py норм.shp аномал1.shp аномал2.shp -o compare.html
```

* Сначала можно прогнать быстро на выборке: `--every 20` (каждый 20-й файл) или `--limit 500`.
* Повторный запуск `extract_features.py` дописывает только новые файлы — можно прервать и продолжить.
* Если известен «здоровый» период (после ремонта/ТО), укажите его:
  `python analyze.py features.parquet -o report --baseline-start 2026-09-01 --baseline-end 2026-09-07`
  Иначе «нормой» считаются первые 20% по времени.

## Что считается по каждому циклу (~1700 признаков)
* **Инженерные (≈150)** — то, что физически говорит об износе:
  * насосы: давление дренажа корпуса MD1–MD6 (рост = внутренние утечки, износ), ошибка/запаздывание угла наклона
    и клапана управления по каждому из 12 насосов, ошибка оборотов частотника;
  * сервоклапаны (12Y102, 12Y069.21/.22, 20Y019, 31Y102, CCyl/LCyl, MB): ошибка «задание–золотник» и запаздывание;
  * ползун: усилие, работа, время прессования и нарастания усилия, нижняя точка, скорости,
    перекос лево-право, **дрейф в покое наверху** (утечки уплотнений);
  * гидростанция: просадка и восстановление высокого давления, температуры и уровни баков, аккумуляторы, зажим штампа;
  * цилиндры CCyl/LCyl: ошибка позиционирования, усилия, скорости; выталкиватели.
* **Сырые** — mean/std/min/max каждого из 307 аналоговых каналов.
* **Дискретные** — доля времени во включённом состоянии и число включений каждого бита.

## Что в отчёте (`report/report.html` + CSV)
| Раздел | Как считается | Файл |
|---|---|---|
| Норма | p1/p5/медиана/p95/p99 каждого признака в базовом периоде | normal_profile.csv |
| Деградация | медиана по дням; устойчивый монотонный уход от нормы (Spearman ρ > 0.6 и сдвиг > 3σ) | trends.csv |
| Аномалии | цикл, где признак отличается от соседних ±25 циклов больше чем на 6 робастных σ, с объяснением | anomalies.csv |
| Остановы | паузы между файлами > 30 мин; что отклонялось в 50 циклах до каждой; повторяющиеся предвестники | stops.csv |
| Датчики | сигналы, которые замерли или дают NaN | — |

Графики в отчёте: карта здоровья «подсистема × день» и общий индекс; тренды деградации; аномалии по подсистемам во времени;
18 групп физических признаков (дренажи MD1–6, 12 насосов, сервоклапаны, масло, давление, аккумуляторы, ползун, цилиндры…)
в реальных единицах и в σ; «было/стало» распределения; матрица корреляций; признаки перед остановами (совмещённые по моменту останова);
связи усилие/работа, ходы штампа/нижняя точка; эволюция формы цикла по дням; аномальные циклы поверх нормального.
Графики формы цикла читают исходные .shp — папка с данными должна быть доступна при запуске analyze.py.

## Как читать «как умирает оборудование»
1. Раздел **Деградация**: признак медленно выходит из серой полосы → это износ. Подсказка «смысл роста» говорит, что обычно за этим стоит.
2. Раздел **Остановы → повторяющиеся предвестники**: если перед многими длинными простоями отклоняется один и тот же признак — это кандидат на сигнал раннего предупреждения.
3. Сверьте даты остановов с журналом ремонтов/простоев (можно добавить его в анализ следующим шагом — тогда предвестники будут привязаны к конкретным отказам, а не просто к паузам).
